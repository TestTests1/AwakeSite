# 3D-вьюер локации «Хвойный» — дизайн

Дата: 2026-07-24
Статус: утверждён

## Проблема

В STALCRAFT есть инструмент `SC_Map_Dump-main` (сторонний, реверс-инжиниринг игрового формата `.mdat`), который умеет экспортировать чанки карты в текстурированный 3D-меш (GLB/glTF). Хочется дать членам клана возможность походить по одной из локаций игры «как персонаж» прямо в браузере на сайте, а не запускать инструмент локально.

Инструмент экспортирует только геометрию блоков чанков (без расставленных игрой объектов — таково ограничение самого `.mdat`-формата, см. `SC_Map_Dump-main/README.md`). Экспорт делается офлайн, разово, не в рантайме сайта.

## Решение

Один сквозной пайплайн:

1. Офлайн-экспорт локации `tournament_hvoiny` (кодовое название арены «Хвойный» в `map_cache`, единственное совпадение по имени, подтверждено пользователем — 6 регионов, ~15 Мб сырых `.mdat`) в оптимизированный `.glb`.
2. Бэкенд раздаёт этот `.glb` по авторизации (Member+) через новый эндпоинт.
3. Новая вкладка `/world` на сайте — 3D-сцена (React Three Fiber + Rapier), персонаж от первого лица с гравитацией и коллизиями.

## Асset-пайплайн (выполняется разово, не часть деплоя сайта)

Все пути на машине разработки:
- Игра: `D:\SteamLibrary\steamapps\common\STALCRAFT` (`map_cache\5.0\tournament_hvoiny`, `modassets\assets\stalcraft\...`).
- Blender: `D:\SteamLibrary\steamapps\common\Blender\blender.exe` — **не используется** в этом пайплайне: `.blend`-шаг оригинального инструмента нужен только для редактирования в Blender, веб-вьюеру нужен только `.glb`, который `tools/mdat_obj_export.py` производит самостоятельно, без Blender.

Шаги:
1. Отдельное Python-окружение с зависимостями `SC_Map_Dump-main/requirements.txt` (`Pillow`, `cryptography`, `zstandard`).
2. Прямой вызов `SC_Map_Dump-main/tools/mdat_obj_export.py` с `input = map_cache/5.0/tournament_hvoiny` (скрипт принимает как файл региона, так и директорию с несколькими `.mdat`), плюс текстурные пути (`--texarr`, `--ctm-dir`, `--map-blocks`, `--weather-palettes`) и флаги `--double-sided --force-mask --hide-invisible` (как в штатном пайплайне `modules/exporter.py`). Результат — сырой `.glb`.
3. Оптимизация сырого `.glb` через `gltf-transform` CLI (`npx @gltf-transform/cli optimize`): weld, dedup, prune, компрессия геометрии (meshopt/draco), уменьшение текстур. Точный итоговый размер заранее не известен (зависит от фактической геометрии арены) — если после оптимизации файл всё ещё слишком тяжёлый для комфортной загрузки в браузере, дожимается сильнее на этом же шаге (агрессивнее упрощение геометрии/текстур).
4. Готовый `.glb` кладётся в бэкенд как приватный файл-ассет (см. «Бэкенд»), не коммитится в git frontend и не лежит в публичном `wwwroot`.

## Бэкенд

- Файл: `src/Awake.API/MapAssets/hvoiny.glb` (новая папка, не публичная статика).
- Новый эндпоинт `GET /api/maps/hvoiny/model`, `[RankAuthorize(UserRank.Member)]`, стримит файл (`FileStreamResult`, `Content-Type: model/gltf-binary`, `enableRangeProcessing: true` для прогресса загрузки в браузере и частичных запросов), кэш-заголовки на неизменяемый контент.
- Без БД, без списка локаций/метаданных — на первую версию ровно один эндпоинт под ровно одну локацию. Мультилокационность не проектируется заранее.
- 404, если файл-ассет отсутствует на диске (не должно происходить в норме, но обрабатывается явно, а не падает 500).

## Фронтенд

- Новый роут `_auth.world.tsx` (доступен Member+, как остальные `_auth`-вкладки; ранг-гейтинг уже работает на уровне layout-роута, отдельно не реализуется). Пункт меню — например «Мир» или «3D-карта».
- Стек: `@react-three/fiber` + `@react-three/drei` + `@react-three/rapier` (физика/коллизии/капсульный контроллер персонажа) — новые зависимости фронтенда.
- Загрузка модели: не через прямой `<Canvas><primitive src=url>`-подход, а через существующий авторизованный `apiClient` (axios, `responseType: 'arraybuffer'`, с колбэком прогресса загрузки) → `GLTFLoader.parse(...)`. Так JWT-авторизация естественно работает без отдельного мидлвара для статики.
- Экран загрузки с прогресс-баром на время скачивания/парсинга модели.
- Сцена:
  - `RigidBody type="fixed"` с коллайдером карты (trimesh; если окажется, что полный меш слишком тяжёлый для кукинга физики Rapier — коллайдер строится на отдельной упрощённой геометрии, а не на визуальной; решается по факту при реализации).
  - Кинематический капсульный контроллер персонажа: гравитация, WASD-движение относительно направления взгляда, прыжок на пробел.
  - Pointer lock по клику на канвас (курсор блокируется, обзор мышью), Esc — выход из pointer lock.
  - Точка спавна — фиксированная координата внутри арены, подбирается один раз при реализации (raycast вниз до пола после загрузки модели).
  - Освещение — простое (ambient + directional); биомный тон уже запечён в вершины/текстуры самим экспортёром (`--weather-palettes`), полноценную систему освещения повторять не нужно.

## Крайние случаи

- Браузер без WebGL — понятное сообщение вместо пустого/сломанного канваса (простой feature-detect перед созданием `<Canvas>`).
- Дыры в геометрии (voxel-экспорт может давать пробелы на границах чанков/непокрытые формы) → игрок проваливается сквозь пол — невидимая «пол-ловушка» далеко внизу сцены + кнопка «Вернуться на точку спавна», телепортирующая персонажа обратно.
- Ранг пользователя падает ниже Member во время активной сессии на странице — обрабатывается тем же общим механизмом, что и все остальные `_auth`-разделы, отдельно не реализуется.
- Медленная сеть / большой файл — виден прогресс-бар, взаимодействие с канвасом заблокировано до полной загрузки.

## Тестирование

- Бэкенд: юнит-тесты `MapsController`/хендлера — ранг-гейтинг (по образцу существующих `RankAuthorize`-тестов), 404 при отсутствии файла-ассета, корректный `Content-Type`.
- Фронтенд: в репозитории нет тестового раннера вообще (нет `test`-скрипта в `package.json`) — как и для прочих визуальных фич, полагаемся на ручную проверку на дев-стенде: загрузка модели с прогрессом, движение WASD, коллизии со стенами и полом, гравитация/прыжок, pointer lock (вход/выход), поведение при провале за пределы геометрии и кнопка возврата на спавн.
